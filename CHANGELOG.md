# Unreleased — simplification pass, phase 1 (deletions)

Removes what earlier versions left behind. Nothing visible changes except the removals below.
Phases 2–7 are in [SIMPLIFICATION-HANDOFF.md](SIMPLIFICATION-HANDOFF.md); progress and what
has been verified, and how, are in [docs/STATUS.md](docs/STATUS.md).

- **v6 top bar removed** (`quickshell/bar/`, `bar-entry.qml`, `preview.qml`, `tray.qml`,
  `TrayStrip`). The rail clock's time format moves to `[clock] timeFormat`.
- **Controls diagnostic window removed** (`illuminated controls`, `isolate controls`, the
  `controls` bind action). It shipped enabled and bypassed `BrightnessState`.
- **`illuminated migrate` removed** (v2 `preferences.json`/`machine.json` conversion).
- **v6 compatibility shims removed.** Card tilt comes only from `reading.options.rotation`
  (the Herbarium "Align cards to grid" toggle now sets it); the confirmation timeout comes
  only from `reading.options.confirmTimeout`.
- **Five reading options with no implementation removed.**
- A 2 Hz timer in the notification hub that updated an unread property is gone.
- The `Materials.js` facade moved from `quickshell/materials/` to `scripts/skin/` (tests and
  the skin build only); `CommandAction.qml` moved from `tools/` to `services/`.
- The tree is now a Git repository; `checkpoints/` (history bundles, foundation tarball) and
  `artifacts/` (test logs) are no longer part of it. The compositor include evidence moved to
  `docs/evidence/compositor-includes/`. Superseded reports (NEXT-SESSION, HARDENING,
  RUNTIME-REPORT, CARD-HARDENING-V2, CONFIG-V3, DEVELOPMENT-REPORT, VALIDATION) are deleted;
  Git history keeps them.

### Removed keys

`illuminated apply` now rejects these in `config.toml`:

| Removed | Use instead |
| --- | --- |
| `features.bar`, `[bar]` (all keys), `[bar.opens]`, `dimensions.barHeight` | the rail (`[rail]`); time format: `clock.timeFormat` |
| `features.controls` | — |
| `appearance.highLegibility` | `reading.preset = "accessibility"` |
| `battery.lowChargeNumeral` | `reading.options.lowChargeNumeral = "on"` |
| `deck.rotation`, `deck.aligned` | `reading.options.rotation` (`full` 4°, `reduced` 2°, `off` aligned) |

`ui.json` entries for removed keys are ignored, not rejected.

# v6 — real-hardware findings, short labels, grid-aligned decks

From the Inspiron run of v5.1 (GPU renderer: every deck renders whole; the
missing-card symptom is specific to the software renderer).

- **Bar startup (F1, F2, F4).** The first Hyprland refresh could land before the
  monitor list, leaving "Waiting for Hyprland" for 10–12 s and no active workspace
  until the next event. The adapter now re-asks every 250 ms until a focused
  monitor with an active workspace exists (at most 10 s, so it never becomes
  polling), and seeds the active workspace once from `hyprctl -j activeworkspace`
  while Hyprland's objects are still empty. Error text now says which part is
  missing instead of always "disconnected". *Fix unverified on hardware.*
- **Stale title (F3).** The window title is used only while that window is on the
  monitor's active workspace; an empty workspace reads "Workspace N".
- **Charge Remaining (F5).** Time to full while charging, time to empty on
  battery, "—" on AC otherwise (was 423:00 at full).
- **Profile (F6).** power-profiles-daemon is now a dependency: installed by
  `--install-dependencies`, checked by `doctor`, documented.
- **Mixer (F7, F8).** The Mixer link is sized to its word (the focus hairline sat
  on the card's bottom edge). On portrait cards (Devices) it is a footer line
  instead of a quarter column that elided to "Mi…".
- **Short labels (F8).** New `[cards.<kind>].short`: chins and back headers use it
  only when the title would not fit beside the value. Defaults: Mic, Letters,
  Quiet, Net.
- **Grid-aligned decks.** New `deck.aligned` (also a Herbarium toggle): no tilt and
  whole-pixel placement, which removes the staircased hairlines and fringed text
  on low-DPI screens.
- **Minor.** `status` reports `configSource`, `resolvedPath` and `uiPath` (F9);
  the Herbarium sheet names the real ui.json and config paths (F11); defaults
  load synchronously from a generated `config/defaults.js`, removing the ~100
  "Unable to assign [undefined]" startup warnings (F12); `validate.sh` shows
  qmllint warnings without failing unless `STRICT_LINT=1` (F13). The static QML
  test also rejects properties named `id` and catches one-line declarations.

# v5.1 — fixes from the v5 cloud run

- **Cards failed to load:** `CardFill.qml` declared a property named `bottom`,
  which redeclares Item's FINAL anchor line, so no card could be created; six
  suites failed with it. Renamed. `tests/qml-static.test.cjs` now rejects any
  property that redeclares an Item property (it fails on v5).
- **Neighbouring cards partly missing** (software renderer, persisted after redraw):
  suspected culling under opaque geometry that overhung its clip on rotated cards.
  Nothing overhangs any more: fills and patina are intersected with their own
  area, and bands and the dog-ear are painted in a Canvas. Suspected cause,
  not yet confirmed; re-check the session screenshots.
- **audio:** the card's level fill carries `service-level-fill` again (full card
  height, width = level × card width), which the suite measures.
- **session-ui:** the "unarmed click is ignored" step uses a 10 s arming window;
  2 s was shorter than its own pointer, screenshot and IPC calls.
- **single-config:** fails on QML load/script errors in its log, so an empty
  deck no longer passes.

# v5 — runtime fix, Herbarium cards, Sleep / Shut Down / Reboot

**Fix (from the v4 runtime report).** `BarContent.qml` assigned `implicitWidth`
on the tray `Loader`, which Qt rejects, so the bar failed to load. The binding is
gone (a Loader already takes its item's implicit size). `tests/qml-static.test.cjs`
now rejects implicit-size assignments on any `Loader`.

**Colours.** Palettes are the Herbarium light and dark values (DESIGN-SYSTEM.md
§3), with cardstock, sunken, disabled ink, focus core/fringe and Sleep tokens. A
new `[semantic]` table holds the meaning colours, one value in every mode. The
high-contrast palette is gone: `appearance.highLegibility` is a modifier over
either mode (card text switches to the sans, low-charge numeral on). A config
still set to `mode = "highContrast"` fails `apply` with a pointer to the
modifier; a stale value in ui.json renders as dark. Compositor active borders
use the focus core colour.

**Cards.** Every card has a ~10 px cardstock frame, a grey placeholder art panel
and a chin with live blackletter text (`typography.blackletter`; label left,
glyph and value right, shrinking before eliding). State colour lives on the
cardstock only; text over a wash is inked per region. Sound and Light fill the
cardstock left to right (Light's art dims with level); mute is a greyed fill and
*Muted*, not a flip or red shift. Charge has a green wash rising bottom-up,
canary frame bands while charging, a canary wash and `92% • held` when held,
bolt/plug glyphs and an optional low-charge numeral (`battery.lowChargeNumeral`).
Network: off / verdigris bands while connecting / copper with a verdigris border
that grows in four signal stages / red bands when a connection fails. Bluetooth:
off / azure chin / azure bands / solid azure / red bands. Backs carry the front's
surface across the whole face (Reboot and charging use tonal interior bands).
Sound, Network and Bluetooth act on click and turn over from a dog-ear; the
Sound back lists outputs with *Mixer*, Network shows the connected and strongest
networks with *See All ›*, Bluetooth lists connected devices with *Devices ›*,
Charge shows Profile / Remaining / Limit. Light has no back. Titles follow the
settled wording (Sound, Light, Charge, Network, Shut Down, Log Out). Selected
cards show a flat two-colour focus edge.

Foil, patina, dithered edges, the numeral's halo and the art are flat stand-ins:
`CardSurface.qml` draws them from descriptors in `CardModel.js`, so textured
versions replace that file only. `tests/card-model.test.cjs` covers every state
mapping and the contrast gates.

**Session.** The deck is Sleep, Shut Down, Reboot. Sleep turns to Sleep / Lock /
Log Out (Log Out confirms inline). Shut Down and Reboot turn to "Confirm?" and
act on a second click after `confirm.armDelay` (400 ms). Escape, a desk click,
selecting another card or `confirm.timeout` (5 s, was 15 s) turns the card back
and cancels. The deck closes once an action starts. `alternatives` now makes a
session card a menu; nested menus are rejected.

**Tests.** `session-ui` is rewritten for the new deck (arming, Escape, desk
click, timeout, Reboot confirm, inline Log Out, Lock, lock-then-suspend).
`artifacts` follows the new flip rules and deck. None of the QML has been run:
this environment has no Quickshell or qmllint. Every QML file parses with a
tree-sitter QML grammar, and the host suites pass.

# v3 follow-up — Mango autostart, numeric validation, docs

Generated Mango config uses `exec_once=` (was `exec-once=`, which Mango does not
document). Every numeric option has its own range, and whole-number options reject
fractions instead of letting QML truncate them. The Greeter fallback literal was
removed. The testing guide was rewritten for v3, and the stale architecture,
feature and historical-report text was corrected. Uninstall now refuses a
hand-modified install before removing anything; it previously removed the hook,
launcher and generated files first. The stale v2 `configuration/*.example.json`
files were deleted. Deck geometry is tested at 1366x768, and every default deck
must fit on one page at 1280x720 and 1366x768. DEPENDENCIES.md now describes the installer's
actual dependency handling: there is no `--strict-deps`, and `--yes` does not
answer the pacman prompt. `--install-dependencies` now refuses while system
upgrades are pending (`pacman -Qu`), so it never performs a partial upgrade.
New `commands.lockReturnsWhenReady` supports lockers that run until unlock
(plain hyprlock): Lock is never timed out and Sleep refuses. Diagnostics carry
config.toml line numbers. The Mango include uses `source_optional=`. Two new
runtime suites, `single-config` and `session-ui`, are written but not yet run.

# v3 — central configuration and managed install

See docs/CONFIG-V3.md. One user file (`~/.config/illuminated/config.toml`),
validated and compiled by `illuminated apply` into the only file the shell reads.
`config/defaults.toml` is the single source of defaults, types and ranges. A
registry for groups, cards and bar modules replaces the five hardcoded maps.
Keybinds are written once for both compositors. One-command install and
uninstall for Hyprland/Mango, with a reversible marked block in the compositor
config. Fixed: partial menu overrides wiped the other groups, wrong-type values
were silently ignored, shell changes shadowed by machine.json failed silently,
and Lock had no card. Breaking: preferences.json/machine.json →
`illuminated migrate`; install location moves to ~/.local/share/illuminated.
